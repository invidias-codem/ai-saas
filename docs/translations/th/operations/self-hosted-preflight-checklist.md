# รายการตรวจสอบความพร้อมและการทดสอบเบื้องต้นสำหรับการติดตั้งแบบโฮสต์เอง

## วัตถุประสงค์

กำหนดรายการตรวจสอบก่อนใช้งานและการทดสอบเบื้องต้นสำหรับการติดตั้ง Lattice แบบโฮสต์เองในองค์กร

เอกสารนี้ตอบคำถามสำคัญว่า:

## “เราจะรู้ได้อย่างไรว่าการติดตั้งใหม่พร้อมใช้งานจริง?”

ควรใช้สำหรับ:
- การติดตั้งในองค์กรครั้งแรก
- การตรวจสอบความถูกต้องของการติดตั้ง
- การตรวจสอบหลังอัปเกรด
- การคัดแยกและแก้ไขปัญหาฝ่ายสนับสนุน

---

## การตรวจสอบสองระดับ

### ระดับ 1 — ตรวจสอบก่อนใช้งาน
ตรวจสอบการตั้งค่าและการเชื่อมต่อบริการก่อนเริ่มใช้งานตามปกติ

ตัวอย่าง:
- มีตัวแปรสภาพแวดล้อมที่จำเป็น
- เชื่อมต่อฐานข้อมูลได้
- เข้าถึงพื้นที่จัดเก็บได้
- ตั้งค่าการยืนยันตัวตนแล้ว
- มีข้อมูลลับที่จำเป็นครบถ้วน

### ระดับ 2 — ทดสอบการใช้งานเบื้องต้น
ตรวจสอบว่าเวิร์กโฟลว์ที่ผู้ใช้ใช้จริงทำงานได้

ตัวอย่าง:
- เข้าสู่ระบบได้
- สร้างหรือเปิดเวิร์กสเปซได้
- อัปโหลดเอกสารได้
- แสดงตัวอย่างเอกสารได้
- ถามคำถามโดยอ้างอิงเอกสารได้

ทั้งสองระดับจำเป็นต่อการรับรองความพร้อมของการติดตั้งในองค์กร

---

## รายการตรวจสอบก่อนใช้งาน — พื้นฐานโหมด A

### การตั้งค่าหลักของแอป
- [ ] ตั้งค่า `NEXT_PUBLIC_APP_URL` ถูกต้อง
- [ ] ตั้งค่า `NODE_ENV` เหมาะสม
- [ ] มีข้อมูลลับของแอปที่จำเป็น
- [ ] ตั้งค่าข้อมูลลับของงาน cron/เส้นทางภายในแล้ว

### การยืนยันตัวตน
- [ ] มีผู้ให้บริการหรือการตั้งค่าการยืนยันตัวตน
- [ ] URL สำหรับ callback/redirect ตรงกับ URL ที่ติดตั้ง
- [ ] ขั้นตอนทดสอบเข้าสู่ระบบทำงานได้ หรืออย่างน้อยตั้งค่าไว้ถูกต้อง

### ฐานข้อมูล
- [ ] มี URL หรือการตั้งค่าฐานข้อมูลหลัก
- [ ] มีข้อมูลรับรอง service role/ผู้ดูแลระบบเมื่อจำเป็น
- [ ] แอปเชื่อมต่อฐานข้อมูลได้สำเร็จ
- [ ] ใช้ migration เรียบร้อยแล้ว

### พื้นที่จัดเก็บ
- [ ] มี bucket หรือการตั้งค่าพื้นที่จัดเก็บ
- [ ] แอปเขียนข้อมูลลงพื้นที่จัดเก็บได้
- [ ] แอปอ่านข้อมูลจากพื้นที่จัดเก็บได้
- [ ] ขั้นตอนอัปโหลดแบบลงนามทำงานได้หากใช้งาน

### การตั้งค่าโมเดล/ผู้ให้บริการ
- [ ] ตั้งค่าผู้ให้บริการแชต/การให้เหตุผลที่รองรับอย่างน้อยหนึ่งราย
- [ ] ตั้งค่าผู้ให้บริการ embedding ที่รองรับอย่างน้อยหนึ่งราย
- [ ] เข้าใจกลไกเลือกผู้ให้บริการและ fallback

### ตรวจสอบการเปิดใช้ฟีเจอร์
- [ ] ระบบย่อยเสริมที่ปิดใช้งานไม่จำเป็นต่อการติดตั้งพื้นฐาน
- [ ] การไม่มีตัวแปรสภาพแวดล้อมของระบบเชื่อมต่อเสริมไม่ทำให้ฟังก์ชันหลักล้มเหลว

---

## รายการทดสอบเบื้องต้น — พื้นฐานโหมด A

### 1. การเริ่มทำงานของแอป
- [ ] แอปโหลดได้ที่ URL สาธารณะ
- [ ] หน้าเว็บสาธารณะแสดงผลสำเร็จ
- [ ] ส่วนของแอปสำหรับผู้เข้าสู่ระบบโหลดได้หลังยืนยันตัวตน

### 2. การยืนยันตัวตน
- [ ] ผู้ใช้เข้าสู่ระบบได้
- [ ] สร้างเซสชันสำเร็จ
- [ ] เข้าถึงส่วนที่ต้องยืนยันตัวตนได้

### 3. เวิร์กสเปซ
- [ ] สร้างหรือเปิดเวิร์กสเปซได้
- [ ] เส้นทางที่อยู่ภายใต้เวิร์กสเปซโหลดได้
- [ ] ไม่มีขั้นตอนเริ่มใช้งานวนซ้ำหรือข้อผิดพลาดการตั้งค่าซ้ำที่ขวางการใช้งานครั้งแรก

### 4. การอัปโหลดเอกสาร
- [ ] อัปโหลดเอกสาร TXT/MD/PDF ได้
- [ ] อัปโหลดสำเร็จโดยไม่มีข้อผิดพลาดในการส่งข้อมูล
- [ ] สร้างและบันทึก URI ของพื้นที่จัดเก็บแล้ว
- [ ] เอกสารปรากฏในหน้าเวิร์กสเปซ

### 5. การแสดงตัวอย่างเอกสาร
- [ ] แสดงตัวอย่างเอกสารที่อัปโหลดและประมวลผลแล้วได้
- [ ] ตัวอย่างเอกสารแสดงเนื้อหาที่สกัดได้อย่างอ่านรู้เรื่อง
- [ ] เข้าใจและทดสอบการทำงานของเอกสารส่วนตัวและเอกสารเวิร์กสเปซตามกรณี

### 6. การถามคำถามจากเอกสาร
- [ ] ส่งคำถามโดยอ้างอิงเอกสารได้
- [ ] โมเดลใช้เนื้อหาจริงจากเอกสารที่อัปโหลด ไม่ใช่เพียงข้อมูลชื่อไฟล์
- [ ] ไม่มีความไม่ตรงกันของ RPC ที่ใช้ดึงข้อมูลจนขวางการเพิ่มบริบท

### 7. หน่วยความจำและบริบทพื้นฐาน
- [ ] ระบบประกอบบริบททำงานโดยไม่มีข้อผิดพลาดร้ายแรง
- [ ] รวมบริบทของเอกสารเมื่อควรใช้
- [ ] ไม่พบข้อมูลข้ามขอบเขตระหว่างเวิร์กสเปซหรือเอกสาร

### 8. การป้องกัน API หลัก
- [ ] เส้นทางภายใน/cron ที่ได้รับการป้องกันปฏิเสธการยืนยันตัวตนที่ไม่ถูกต้อง
- [ ] เส้นทางภายใน/cron ที่ได้รับการป้องกันยอมรับการยืนยันตัวตนที่ถูกต้อง

## สถานการณ์ทดสอบเบื้องต้นที่แนะนำ

การติดตั้งในองค์กรขั้นพื้นฐานควรผ่านขั้นตอนต่อไปนี้:

1. ติดตั้งแอปและฐานข้อมูล
2. ตั้งค่าการยืนยันตัวตนและพื้นที่จัดเก็บ
3. เข้าสู่ระบบ
4. สร้างหรือเปิดเวิร์กสเปซ
5. อัปโหลด PDF
6. ตรวจสอบว่าเอกสารปรากฏในรายการ
7. แสดงตัวอย่างเอกสาร
8. ถามว่า “สรุปเอกสารที่ฉันเพิ่งอัปโหลด”
9. ได้รับคำตอบที่อ้างอิงเนื้อหาจริงในเอกสาร

หากขั้นตอนนี้ไม่ผ่าน ยังไม่ควรถือว่าการติดตั้งพร้อมใช้งานจริง

---

## การจำแนกสาเหตุของความล้มเหลว

เมื่อการตรวจสอบหรือทดสอบล้มเหลว ให้จัดประเภทสาเหตุให้ชัดเจน

### ปัญหาการตั้งค่า
ตัวอย่าง:
- ไม่มีตัวแปรสภาพแวดล้อม
- รูปแบบข้อมูลลับไม่ถูกต้อง
- ใช้ผู้ให้บริการร่วมกันในรูปแบบที่ไม่รองรับ

### ปัญหาบริการที่พึ่งพา
ตัวอย่าง:
- เชื่อมต่อฐานข้อมูลไม่ได้
- เข้าถึงพื้นที่จัดเก็บไม่ได้
- URL callback ของการยืนยันตัวตนไม่ตรงกัน

### ปัญหาเวิร์กโฟลว์ผลิตภัณฑ์
ตัวอย่าง:
- อัปโหลดสำเร็จแต่แสดงตัวอย่างไม่ได้
- มีเอกสารแต่โมเดลวิเคราะห์ไม่ได้
- การสร้างเวิร์กสเปซวนซ้ำหรือสร้างข้อมูลซ้ำ

### ปัญหาขอบเขตและสิทธิ์
ตัวอย่าง:
- ใช้บริบทผิดเวิร์กสเปซ
- ข้ามการดึงเอกสารส่วนตัวโดยไม่ถูกต้อง
- การแสดงตัวอย่างต้องการ workspaceId ทั้งที่ไม่ควรต้องใช้

---

## ข้อแนะนำสุดท้าย

ควรถือว่าการติดตั้งในองค์กรพร้อมใช้งานเมื่อผ่าน:
- การตรวจสอบการตั้งค่า
- การเชื่อมต่อบริการที่จำเป็น
- การทดสอบเวิร์กสเปซ การอัปโหลด การแสดงตัวอย่าง และการถามคำถามจากเอกสาร

นี่คือมาตรฐานขั้นต่ำของการโฮสต์ระบบเองสำหรับองค์กรที่เชื่อถือได้
