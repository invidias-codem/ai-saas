# SEO Strategy

## Purpose

This document defines an SEO strategy that matches the current Lattice OS identity.

The goal is not generic "AI tool" traffic. The goal is to attract users, collaborators, and evaluators who are specifically looking for:
- memory-native AI workflows
- AI workspaces
- model routing / hybrid inference
- persistent context and retrieval-backed systems
- architecture-aware AI platforms

---

## Positioning Principle

Lattice OS should rank as a **memory-native AI operating layer** and **AI workspace platform**, not as a generic chatbot directory listing.

That means the SEO language should consistently reinforce:
- **Lattice OS** = the product/platform
- **Weaver** = the customer-facing intelligence
- **Relay** = the internal orchestration layer
- **UCOL** = the routing/context/execution contract

Avoid centering legacy or vague phrases such as:
- "AI assistant"
- "chatbot"
- "Genie"
- broad hype language without a technical differentiator

---

## Primary SEO Themes

### 1. Memory-native AI
Use this as a core theme across metadata, landing copy, docs, and editorial content.

Target ideas:
- memory-native AI
- persistent AI memory
- AI with memory across sessions
- workspace memory for AI

### 2. AI workspace / operating layer
Use this to distinguish the product from single-chat surfaces.

Target ideas:
- AI workspace platform
- AI operating layer
- workspace-native AI
- context-aware AI workspace

### 3. Hybrid inference and model routing
Use this to capture technically aware search intent.

Target ideas:
- hybrid AI inference
- model routing
- self-hosted plus frontier AI
- multi-model AI orchestration

### 4. Context infrastructure / UCOL
Use this selectively for deeper technical pages and docs.

Target ideas:
- context orchestration
- prepared context
- retrieval and memory architecture
- AI context layer

## Messaging Rules

### Prefer
- memory-native AI workspace
- AI operating layer
- persistent context
- model-aware routing
- hybrid inference
- workspace intelligence
- shared context layer

### Avoid overusing
- chatbot
- assistant
- all-in-one AI
- smartest AI
- best AI app
- fully autonomous agent

### Identity discipline
- Use **Lattice OS** in product/page titles and canonical descriptions.
- Use **Weaver** when describing the interactive user-facing intelligence.
- Use **Relay** only where orchestration internals are actually relevant.
- Use **UCOL** on architecture/docs pages where the technical contract is the point.

---

## Content Architecture

### Landing / product pages
Focus on commercial-intent and platform-intent terms:
- memory-native AI workspace
- hybrid inference platform
- AI operating layer
- persistent context for AI work

### Documentation pages
Focus on trust, architecture, and technical-intent terms:
- system architecture
- runtime routing
- memory and context architecture
- public routes / trust boundaries
- environment variables / deployment / truth surfaces

### Blog/editorial pages
Focus on explainers and comparison-style intent:
- how memory-native AI differs from chatbot UX
- when to use hybrid inference
- why model routing matters
- prepared context vs raw chat history
