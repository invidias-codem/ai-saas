# From Genie to Lattice OS: Brand Architecture for Memory-Native Products

## The Naming Problem

"Genie" was a single-product brand. It implied a monolithic AI assistant that does everything — chat, code, images, analysis. That was never the architecture. Lattice OS is a memory-native operating system with three distinct layers: infrastructure, customer face, and packaged expertise.

The brand migration was not a rebranding exercise. It was a structural correction. The codebase was already layered; the brand needed to match.

## Layer 1: Lattice OS — The Infrastructure

Lattice OS is the deterministic substrate. It owns the routing layer that decides which model handles each request, the telemetry that audits every interaction, the edge functions that minimize latency, and the durable substrate that persists state across sessions.

It is the engine that actually drives ROI. Without it, the products above it have no memory, no routing, and no observability.

The codebase reflects this. The `lib/ucol/` directory contains the routing logic, the provider resolver, and the context assembler. The `lib/telemetry/` directory contains the UDIF 2.0 schema and the interaction audit emitter. The `lib/world-model/` directory contains the causal graph and the Delta Engine.

Lattice OS is not a product the user signs up for. It is the substrate that makes the products possible.

## Layer 2: Weaver — The Customer Face

Weaver is the conversational face. It is the UI, the conversation interface, the Slack integration, and the Code Builder. When a user types a message in the dashboard, they are talking to Weaver. When they generate code, they are using Weaver Code. When they share a link on Bluesky, the agent identifies as Weaver.

The codebase reflects this. The `app/[locale]/(dashboard)/(routes)/conversation/` directory contains the conversation UI. The `app/[locale]/(dashboard)/(routes)/code/` directory contains Weaver Code. The `lib/agents/bluesky/prompts/tech-genie-bluesky.sudo.md` file still carries the legacy "Weaver" identity in its prompt.

Weaver is the product brand. Lattice OS is the infrastructure brand. They are not interchangeable.

## Layer 3: Chameleon Consultant — The Packaged Expert

The Chameleon Consultant is the persona system. It is the DevOps Security Reviewer, the Headless Commerce Architect, the B2B Sales Strategist. It is the specific expertise that a user rents on demand. Unlike Weaver, which is a general conversational interface, the Consultant is a tamper-evident, stateful expert with a nonce-anchored identity, a minimum model tier, and a post-generation critic that catches drift.

The codebase reflects this. The `lib/consultant/` directory contains the Persona State Machine, the Domain Gate, and the Post-Generation Critic. The `lib/constants/personas.ts` file contains the curated persona definitions. The `app/[locale]/(dashboard)/(routes)/expert/[id]/` directory contains the operator interface for persona management.

The Chameleon Consultant is a product of Lattice OS, delivered through Weaver.

## Why Genie Failed as a Brand

"Genie" implied a single entity that does everything. It suggested magic — a stochastic chat wrapper that answers any question. Engineering teams do not buy magic. They buy deterministic systems with observable boundaries.

The original multi-model Code Builder built under the Genie moniker was structurally sound. It used the same UCOL routing, the same context budgets, the same review gates that Lattice OS uses today. But the brand name contradicted the architecture. "Genie" suggested a monolith; the codebase delivered a layered system with sovereign telemetry, causal lineage, and nonce-anchored persona boundaries.

The brand migration to Lattice OS / Weaver / Chameleon Consultant resolves this. Each layer has a distinct identity, a distinct audience, and a distinct codebase footprint. Investors and press can distinguish between the platform and the product. Engineers can trace the brand claim back to the actual directory structure.

## The Operator's View

The landing page at `/` presents Lattice OS as the infrastructure. The dashboard presents Weaver as the product. The expert page at `/expert/[id]` presents the Chameleon Consultant as the persona. The operator never sees the brand architecture; they experience it as a seamless stack.

When a user sends a message to Weaver, they do not need to know that UCOL routed it to a specific model, that the context was budgeted at 20K characters, or that the response was critiqued by a post-generation quality gate. They just get a response that is grounded in their workspace data, consistent with the active persona, and auditable in the admin logs.

The complexity is abstracted away. The reliability remains.

## The Golden Line

A brand is not a logo. It is a structural claim about how the system is organized.

Lattice OS claims to be an operating system. Weaver claims to be the customer face. The Chameleon Consultant claims to be the packaged expert.

If the brand does not match the architecture, the architecture will eventually fail. The migration from Genie to Lattice OS was not cosmetic. It was the first step in building a system that can actually deliver on its promises.
